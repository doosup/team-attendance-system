# 근태 제도 해석과 결정 로그

과제의 근태 제도에서 애매한 부분을 어떻게 해석했는지, 그 근거와 함께 기록한다. README의 "제도 해석" 섹션의 원본이다.

## 결정 원칙

1. **제도 문구를 먼저 따른다.** 문구로 답이 나오면 그대로 해석하고, 추측해서 규칙을 더하지 않는다.
2. **문구에 없는 부분은 팀원에게 불리하지 않게, 그리고 단순하게.** 리드가 사이드 프로젝트로 만드는 내부 도구라는 설정에 맞춘다.
3. **경계값은 한 가지 방식으로 통일한다.** 초 단위까지 보고, "까지"는 그 시각을 포함한다.
4. **기록은 지우지 않는다.** 변경과 취소는 새 이력·원장 이벤트로 남긴다 (FR-LOG-01).
5. **로컬 실행을 해치지 않는다.** 외부 API나 별도 설치에 의존하지 않는다.

(ATT-48) | **반일 OFF**: 승인할 때 그날 출근 기록을 반일 OFF 사용일로 다시 판정(지각 없음, 4시간 기준, 이미 퇴근했으면 조퇴·근무시간도 다시). 바꾸기 전 판정은 승인 이력 `convertedAttendance`에. **재택**: 늦게 승인돼 10시 넘어 출근하면 지각 그대로. **연차**: 출근 기록을 바꾸지 않음(근무와 차감이 함께 남음) → 당일이면 리드 당일 취소로 바로잡고, 지난 날짜는 승인 확인 창(ATT-46)이 미리 알림 | 반일 OFF는 승인되는 순간 그날이 원문의 "반일 OFF 사용일"이 되므로 그 규칙으로 판정하는 것이 원문에 맞고, 당일 취소로도 고칠 수 없다(긴급 출근이 됨). 재택 지각 면제는 원문 "10:00:00을 넘기면 지각"(FR-ATT-01)에 없는 예외라 넣지 않는다. 승인 전 IP 불허(결정 14)를 택한 비용으로 보고, 리드는 이력에서 승인 시각과 출근 시각을 비교해 판단 |
| A25 | 시계를 미래로 옮겨 OFF 만료가 기록된 뒤 과거로 돌아와 같은 OFF를 쓰면? (ATT-50) | **만료 기록은 "이 지급분은 끝났다"는 표시로만 보고, 빼는 양은 그 시점에 남은 만큼**으로 센다. OFF 잔여는 원장 행을 그대로 더하지 않고 지급분별 남은 수의 합. 원장 행은 그대로(추가 전용 유지) | 만료 행에 저장된 양(-1)을 그대로 빼면 만료와 사용이 겹쳐 잔여가 -1이 된다. 실제 시간에선 생기지 않지만 "현재 시각 변경"으로 시험하는 과제라 평가 중에 나올 수 있다. 계산만 바꾸면 기존 데이터도 고치지 않고 바로잡힌다 |
| A26 | 리드가 정한 초기 비밀번호를 팀원이 계속 써야 하나? (ATT-53) | **본인이 바꿀 수 있다.** 상단 "비밀번호 변경" → 현재 비밀번호 확인 후 새 비밀번호(팀원 등록과 같은 8~72자, 현재와 달라야 함). bcrypt 해시만 저장, 이력 `PASSWORD_CHANGE`에 비밀번호는 넣지 않음. 현재 비밀번호가 틀리면 400(401이면 로그아웃되므로). 첫 로그인 변경 강제·리드의 재설정은 확장 방안 | 리드가 팀원 비밀번호를 계속 아는 상태는 계정 주인을 보장하지 못함. 최소 범위(본인 변경)만으로 그 문제는 풀리고, 강제·재설정은 화면 흐름이 더 필요해 뒤로 |
| A4 | 2026 공휴일 목록 | 법정 공휴일·대체공휴일·지방선거일(6/3). **제헌절(7/17)·노동절(5/1)은 제외** | 제헌절 공휴일 재지정은 확인 못 함. 노동절은 관공서 공휴일이 아님 |

## 반일 OFF 예시 (결정 8 보충)

출근 시각이 자유라서 반일 OFF를 "오전/오후 시간대"가 아니라 **실제 근무시간 4시간**으로 판정한다. 점심 구간을 끼면 1시간 더 있어야 하고, 안 끼면 4시간만 있으면 된다.

| 반일 OFF 날 | 점심 구간 | 머문 시간 | 근무시간 | 판정 |
| --- | --- | --- | --- | --- |
| 07:00 → 11:00 (오전 근무) | 안 겹침 | 4시간 | 4시간 | 정상 (16:00 전 퇴근 허용) |
| 12:30 → 16:30 (오후 근무) | 안 겹침 | 4시간 | 4시간 | 정상 (10:00 이후 출근이지만 지각 아님) |
| 11:00 → 16:00 | 전체 포함 | 5시간 | 4시간 | 정상 |
| 10:00 → 14:00 | 전체 포함 | 4시간 | 3시간 | 조퇴 (15:00까지 있어야 정상) |

- **반일 OFF와 반차의 관계:** 사용하는 날의 규칙은 일반적인 반차와 같고, 다른 점은 잔여를 꺼내는 곳뿐이다. 반일 OFF는 주말·공휴일 근무 보상(30일 만료), 연차는 매월 적립(1일 단위, 만료 없음). 제도에 연차 반차 규정이 없어 만들지 않되(원칙 1), 원장을 0.5일 단위로 설계해 바로 붙일 수 있게 한다.
- **제도 설계에 대한 관찰:** 가장 이른 출근 07:00 + 8시간 + 점심 1시간 = 16:00. 그래서 퇴근 등록이 16:00부터다. 가장 늦은 정상 출근 10:00이면 19:00 퇴근이 된다.

## 확정 스펙 요약

- **출근:** 07:00:00부터 등록. 10:00:00까지 정상, 10:00:01부터 지각. 반일 OFF·긴급 출근 날은 지각 판정 없음
- **퇴근:** 16:00:00부터 등록 (반일 OFF 날은 제한 없음). 출근일 23:59:59까지
- **근무시간:** 퇴근 − 출근 − (11:30~12:30 전체가 포함되면 1시간)
- **조퇴:** 일반일 8시간 미만, 반일 OFF 날 4시간 미만
- **정상 퇴근 가능 시각 (내 카드):** 출근 + 8시간(반일 OFF는 4시간), 점심 구간 포함 시 +1시간. 일반일은 16:00보다 이르면 16:00
- **미기록 퇴근:** 출근은 즉시 저장, 직전 1건 입력을 서버 상태로 강제(닫기 없음), 입력 전 퇴근 거부. 범위는 그날 출근 시각 ~ 23:59:59
- **연차:** 입사 1개월 뒤부터 매월 입사일과 같은 날(없으면 말일)에 +1
- **재택:** 대상 날짜가 속한 달 기준 2회(대기·승인 포함), 이월 없음. 초과는 신청서 전체 예외 신청(사유·리드 승인 필수)
- **OFF:** 승인된 주말·공휴일 근무의 퇴근 시점에 반일 OFF 1개 지급, 30일 뒤 만료, 만료 임박 순 사용
- **원장:** 연차·반일 OFF 분리, 0.5일 단위. 연차 반차는 미구현(확장 방안)
- **기간 신청:** 연차·재택은 시작일~종료일로 한 번에 신청·승인, 영업일만 차감. 반일 OFF·주말 근무는 하루만
- **신청 기한:** 시작일의 직전 영업일 17:00:00까지
- **취소:** 기한 전은 본인이 기간 전체. 당일(23:59:59까지)은 리드만, 하루만, 사유 필수 → 긴급 출근. 복원, 지난 날짜 불가
- **승인:** 리드가 승인·반려(반려 사유 필수). 신청 시 차감, 반려·취소 시 복원. 리드 본인은 자동 승인. 대상일까지 대기 중이면 미승인
- **영업일:** 월~금 중 공휴일 제외, 2026년 공휴일 JSON 고정
- **접속:** 연구실 IP(시드 127.0.0.1) 상시 허용. 재택·주말/공휴일 근무는 승인된 신청의 IP·시간대에서만. 차단 시 "등록된 IP가 아닙니다 (현재 IP: x.x.x.x)"
- **팀 보드:** 팀원은 상태만, 리드는 시각·지각·조퇴까지. 출근 전은 "미출근"(리드에게만 10시 경과 강조)
- **IP 관리:** 리드 전용 API, 현재·마지막 IP 삭제 불가, 최소 형식 검사, 로컬 IPv6 표기 정규화
- **로그인:** JWT 12시간, localStorage
- **시간:** 판정 KST, 현재 시각은 주입 가능한 Clock
- **이력:** 모든 인터랙션을 지우지 않고 추가만 함

## 확장 방안 (구현하지 않음)

- **연차 반차·반반차:** 원장이 0.5 단위라 연차에서 0.5(또는 0.25)를 차감하고 반나절 판정 함수를 재사용
- **유연한 점심시간:** 점심 시작·종료 버튼을 추가하고, 기록이 있으면 실제 점심 시간을, 없으면 11:30~12:30 규칙 적용
- **자정을 넘긴 근무:** 근무일을 출근일에 귀속시키는 규칙 추가
- **다른 연도 공휴일:** `domain/value/holidays.ts`에 연도별 날짜 추가
- **연구실 IP 대역(CIDR):** 사무실 네트워크 전체 허용
- **비밀번호 재설정:** 리드의 임시 비밀번호 발급 + 첫 로그인 시 변경 강제 (본인 변경은 A26으로 구현)
- **httpOnly 쿠키:** localStorage 대신 XSS에 강한 토큰 보관
- **로그인 시도 횟수 제한:** `@nestjs/throttler`로 IP당 15분 10회. 지금은 넣지 않음 — IP 검사로 연구실·승인된 IP에서만 접근 가능하고 사용자가 4명이라, 실패는 LOGIN_FAIL 이력으로 리드가 확인
- **휴가 신청은 어디서든:** FR-SYS-01 때문에 지금은 로그인부터 IP 제한 → 사무실 밖에서 기한 후 예외 신청(A22)을 낼 수 없는 빈틈이 있음. IP 검사를 출퇴근 API(`/attendance/check-in`·`check-out`·직접 입력)에만 걸고, 신청·조회는 JWT만으로 허용. 전역 가드를 경로별 데코레이터로 바꾸면 되고 판정 규칙은 그대로
- **맥 메뉴바 위젯 (Electron):** 기존 `/attendance/check-in`·`check-out`·`today` API를 그대로 쓰는 작은 클라이언트. 토큰은 OS 키체인에 저장, IP·시각 판정은 서버가 하므로 위젯에 업무 로직 없음. 평가 환경의 설치 부담(Electron·네이티브 빌드) 때문에 구현하지 않음
- **데이터 보관 정책:** 데이터가 많아지면 오래된 기록을 보관 테이블로 이동
